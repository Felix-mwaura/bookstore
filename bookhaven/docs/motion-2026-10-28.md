# Motion polish — 28 October 2026

A pass over the storefront's animation, using the motion rules in
[ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)
(`.claude/skills/ui-ux-pro-max/data/motion.csv` and `references/pro-rules.md`)
as the specification. No redesign: same palette, same components, same
layout. What changed is timing, consistency, and what happens when the
reader has asked for less motion.

## What the rules said, and what was wrong

| Rule (from the skill's motion data) | What the store did |
| --- | --- |
| Use shared motion tokens, chosen for distance and complexity — not one copied duration | Every rule carried its own literal: `0.25s`, `0.3s`, `180ms`, `240ms`, `260ms`, `400ms`, `420ms`, `500ms`, and `cubic-bezier(0.16, 1, 0.3, 1)` repeated ten times |
| Linear easing only for constant-rate progress or rotation | The genre deck cross-faded its opacity `linear`, next to a curved transform |
| Press feedback inside 80–150ms, under 2px of travel | Buttons pressed at 180ms with a 2% scale jump; only one class even had a pressed state |
| Deceleration on arrival, acceleration on leaving | Entrances used `ease-out` and `ease-out` for both; no exit curve existed at all |
| Reveal content on scroll with an 8–16px offset, and never hide content needed by crawlers | Nothing revealed: every section appeared at once |
| Pause looping animation when it is off screen or the tab is hidden | The login scene ran four walkers on five infinite loops whether or not anyone was looking |
| One or two focal animations per view, animate transform/opacity only | Already true; the deck's drag and the card tilt are transform-only, and the one layout animation (the genre dot growing into a pill) is now documented as deliberate |

## What changed

**Motion tokens (`app/globals.css`).** Four durations (`--dur-press` 120ms,
`--dur-fast` 180ms, `--dur-mid` 260ms, `--dur-slow` 420ms) and three curves
(`--ease-standard` decelerate, `--ease-entrance` a stronger decelerate,
`--ease-exit` accelerate). Every animation and transition in the file now
references them, so changing the feel of the store is a change in one block.
The values are the ones already in use where they were sensible; the
existing `cubic-bezier(0.16, 1, 0.3, 1)` became `--ease-entrance`.

**Press feedback.** `.btn-primary`, `.btn-secondary` and the deck arrows now
press with `translateY(1px) scale(0.99)` over `--dur-press`. The hover colour
is unchanged at `--dur-fast`.

**Reveal on scroll (`app/lib/reveal.js`, `app/components/HomeClient.js`).**
Home page sections below the fold fade up 12px, once, when they arrive.
Card rows stagger 45ms apart, capped at eight steps. The rules that keep it
from being a liability:

* the attribute is absent in the HTML, so the server-rendered page is fully
  visible to crawlers, to browsers without JavaScript, and if the script
  fails;
* only elements that start **below** the viewport are armed, so the largest
  paint is never delayed and there is no flash of a half-faded hero;
* `prefers-reduced-motion` is checked before anything is armed;
* the observer unobserves each block and the attribute is removed on
  `transitionend`, with a 1.4s timer as the guarantee that a missed event
  can never leave a block invisible;
* unmounting removes any `armed` state left behind.

**The login scene rests when nobody is watching**
(`app/components/KittenScene.js`, `kitten-scene.module.css`). The kittens
pause on `visibilitychange` and when an `IntersectionObserver` reports the
scene off screen, then resume mid-stride. The component gained an effect but
its markup is unchanged, so server and client still render byte-identically.

**Genre deck.** The opacity cross-fade now uses the decelerate curve, and
`will-change: transform` is set only while a finger is down — the one moment
the cards are guaranteed to move every frame — instead of permanently on
five layers.

## What was not added, on purpose

* **Auto-rotating carousel.** The deck never advances on its own. Adding
  rotation would require a stop control, a pause on focus and a
  reduced-motion path, for content the reader can already swipe. The motion
  data's carousel row is a checklist for *if* you auto-rotate; the answer
  here is not to.
* **Scroll-triggered pinning, parallax, split-text.** Nothing in a bookshop
  benefits from a pinned section, and all three are the entries the same
  source marks as the ones that fight native scrolling on a phone.
* **A motion library.** No GSAP, no Framer Motion: every effect here is
  CSS plus one `IntersectionObserver`, so there is no dependency and no
  extra bytes on a Kenyan mobile connection.

## About 21st.dev / Magic MCP

`21st-dev/magic-mcp` is now a thin proxy to an HTTP MCP server at
`21st.dev/api/mcp` that needs an account key (`x-api-key`) and a network path
to that host. Neither is available in this environment, so it could not be
called, and its catalog is React/Tailwind/shadcn components that would have
had to be restyled back into this design system. The part of its documented
workflow that did apply was followed instead — *"match the project's existing
conventions … adapt tokens/props to the project's design system"* — which is
why this pass changed timing tokens and added one small module rather than
importing components.

a look on a real phone: the reveal on a mid-range Android (12 blocks arming
at once is the worst case) and the login scene resuming cleanly after the tab
has been backgrounded.
