# Craft polish — 31 October 2026

A pass over the storefront using two design skills as the specification:

- [pbakaus/impeccable](https://github.com/pbakaus/impeccable) —
  `craft-floor.md` (the things that make a page look assembled rather than
  built), `polish.md` (refinement is not concealed redesign) and `audit.md`
  (accessibility, performance, theming, responsive, integrity).
- [dickwu/apple-design-skill](https://github.com/dickwu/apple-design-skill) —
  the HIG summaries on typography, colour and motion, as a second lens.

No redesign. Same cream paper, navy ink and single sienna action colour; same
layout, copy, components and behaviour. What changed is the layer that is
invisible until it is wrong: contrast, focus, browser surfaces, type
consistency, and the removal of decoration that carried no meaning.

## What the skills found

| Rule | What the store was doing |
| --- | --- |
| Contrast ≥ 4.5:1 for text, ≥ 3:1 for UI | The focus ring was sienna on navy — **2.87:1**. Placeholders were muted at 70%, **3.98:1**. The sold-out button was white on stone-300 |
| Theme the browser's own surfaces | Selection, caret, scrollbar and placeholder were unbranded; the scrollbar was half-themed (webkit only, no `scrollbar-color`) |
| Reduced motion keeps the useful alternative | One rule, `* { transition-duration: 0.001ms }`, which also deleted the colour change that says "added to basket" |
| No kickers above headings | Nine small uppercase lines floated over titles ("Just in", "Browse", "What readers say"), most of them restating the heading |
| One icon system, not emoji | An emoji map shipped in `lib/categories.js`; two toasts and an order timeline used a typed "✓" while the rest of the site drew its ticks |
| One display face, for the page's own title | Playfair appeared on the homepage hero and not on `/books`, category, policy, book-detail, checkout or account pages |
| No hard-coded palette values | 71 `#1B2A4A` / `#B5532F` / `#FAF6EE` literals duplicated the tokens; a raw `green-400` sat beside the themed success colour |
| Every page needs one authored entrance, not six identical ones | Four sections each staggered their items up from 12px, one after another |

## What changed

**Accessibility.** The focus ring is now two-tone — sienna outline plus a cream
halo — so it clears 3:1 on navy as well as on cream, and it no longer forces a
4px radius onto the element it lands on. Every placeholder is at full muted
(6.1:1 on white, 5.7:1 on cream). Input focus rings that were 10–20% alpha are opaque. The sold-out
control is muted-on-subtle (5.2:1) instead of white-on-stone. In-page anchors
clear the sticky header (`scroll-padding-top`), and links in body copy carry an
underline offset rather than relying on colour alone.

**Browser surfaces.** `::selection`, `caret-color`, `accent-color`,
`text-underline-offset`, `scrollbar-width`/`scrollbar-color` and
`::placeholder` are all themed from the tokens; a `prefers-contrast: more`
block darkens muted text and hairlines.

**Motion.** Reduced motion now stops all movement, drops transforms outright
and keeps colour, background and opacity transitions, so a press still answers.
The four duplicated scroll-reveals are down to one staggered grid (new titles,
where the order means something) and two single-block arrivals; the facts
list and the trust strip arrive with their section instead of rippling in
after it.

**Type.** Playfair is on every storefront `h1` — homepage, `/books`, category,
book detail, policy pages, login, account, checkout, order, 404 and the error
page. Micro-labels that are real labels (form fields, filter group headings,
"Step 1 of 3") stay; the decorative captions above headings are gone.

**Integrity.** Every palette value is a token. Four new ones exist because the
colours were real and unnamed: `sienna-soft` and `error-soft` (text on navy),
`warning-strong` (readable amber for low stock), `star-empty` (unfilled stars),
plus `sand` for the sign-in panel and `success-soft` for ticks on navy. Cover
art and the hero illustration keep their hexes — those are drawing, not
theming.

**Guardrail.** `scripts/craft-smoke.mjs` runs in `npm test`. It computes the
palette's contrast ratios from the tokens, asserts the browser surfaces and the
two-tone focus ring exist, checks that reduced motion keeps colour feedback,
and fails if a kicker, an emoji icon map, a dead keyframe, a hard-coded palette
hex or a sans-serif page title comes back.

## Verified, and not

Verified here: `npm test` (642 assertions, including the craft and motion
suites), `next lint` (0 errors), an offline production build, and the rendered
HTML of `/`, `/books`, `/category/fiction`, a book detail page, `/login`,
`/help`, `/about`, `/checkout` and `/account` — one `h1` each, every image
with alt text, every input labelled, no nameless buttons, no rendered kickers,
Playfair on every title.

Not verified here, because this environment has no browser: nothing at all
about how it *looks*; no hover or focus screenshot; no real file upload
through the admin; no synthesised touch, so the tap targets were checked
statically (`min-h-11`) rather than by hand. The duplicate `desktop-query` /
`desktop-category` ids that an HTML scan reports on suspending routes come from
Next's streamed fallback markup — the same header is serialised once hidden and
once visible before hydration — not from rendering the header twice.
